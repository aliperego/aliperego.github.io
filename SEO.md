## 1. How a name query is ranked

Three things decide whether a personal site appears for a query like *Alice Perego astrophysics*:

| Factor | What Google looks at | Who controls it |
| ------ | -------------------- | --------------- |
| **Legibility** | titles, descriptions, headings, structured data that say who the page is about and what for; one canonical address per page; a sitemap | the repository (done) |
| **Identity and authority** | links from pages Google already trusts for your name (ORCID, institute, ADS, GitHub, LinkedIn) to the site; the same name, job title and affiliation everywhere | you |
| **Content** | the words on the page: your name, position, institute and topics in plain sentences; consistent with the profiles | you |

A brand-new domain with no inbound links is not crawled at all until Google learns of it: registering the site in Search Console is what starts the process. After that, a name query typically returns the site within days to a couple of weeks; the namesakes' social profiles are outranked once the identity signals point to this site.

## 3. To do

In order of effect. Steps 1–3 need Alice's own accounts; nothing else in the repository is required.

### 3.1 Register the site in Google Search Console (about 10 minutes)

*Status: the verification tag is published on every page (step 4); steps 5–7 remain.*

1. Sign in at <https://search.google.com/search-console> with Alice's Google account (the owner of the property keeps the search data; other users can be added later under *Settings → Users and permissions*).
2. *Add property* → **URL prefix** → `https://aliperego.github.io/` → *Continue*.
3. Verification method **HTML tag**: copy the code between the quotes of `content="…"` (only the code, not the whole tag).
4. Put it in `_metadata.yml`:

   ```yaml
   seo:
     google-site-verification: "the code"
   ```

   commit, push, wait for the *Publish site* run (about two minutes), then click **Verify**.
5. *Sitemaps* → enter `sitemap.xml` → *Submit*: the report should show "Success" and 3 discovered URLs. (Google also finds the sitemap through `robots.txt`; submitting it makes the fetch visible in the report, with any errors. A site this small would be indexed from the home page alone, so the report is a check, not a requirement.)
6. *URL inspection* → paste `https://aliperego.github.io/` → *Request indexing*; repeat for `publications.html` and `cv.html`.

Expected: the home page indexed within a few days; *Performance* then shows the queries the site appears for.

### 3.2 Link to the site from the profiles that already rank for the name

| Where | What |
| ----- | ---- |
| GitHub profile (`github.com/aliperego`) | website field → `https://aliperego.github.io`; update the bio (position and institute) |
| Repository *About* (GitHub, this repository → ⚙ next to About) | *Website* → `https://aliperego.github.io` |
| ORCID (`0009-0001-0670-2738`) | *Websites & social links* → the site; INSPIRE and ADS pick it up from ORCID |
| LinkedIn | *Contact info → Website* |
| Institute | ask for the URL on the Artemis / OCA team or staff page |
| Google Scholar | create a profile if there is none; *Homepage* → the site; then add its URL to `_metadata.yml` → `person.scholar` |

Every link added to `_metadata.yml` → `person` (`github`, `ads`, `scholar`) is also published in the structured data as `sameAs`, which tells Google that these profiles and the site are the same person.

### 3.3 Replace the placeholders

*Done on 19 September 2026: every section has its text.* Google indexes the text of the pages, so the priority was:

1. **In a nutshell** (~120–150 words): name, position, institute and city, supervisors, the thesis subject, the topics, in plain sentences.
2. **Tagline** (~15 words) under the name.
3. **Research** themes, **Proposals**, **Tools**, **Get in touch**, **Personal interests**.

Use the same wording for the position and institute as on ORCID, LinkedIn and the institute page.

## 5. Keeping it that way

- **Do not rename** pages or the CV file: the canonical URLs and the links from the profiles must keep working.
- **New page:** give it a `description` in its front matter (`GUIDE.md` §14); it enters the sitemap automatically.
- **Changed position or institute:** update `_metadata.yml` → `person` (title, structured data and descriptions follow) and the same fields on ORCID, LinkedIn and GitHub.
- **New paper or talk:** add it to the `.bib` files or `data/`; regular changes keep the site crawled.
- After any of these, push and let the *Publish site* workflow deploy; Search Console picks the changes up on its next crawl, or immediately after *Request indexing*.
